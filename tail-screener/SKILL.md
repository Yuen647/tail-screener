# 沪深 A 股短线研究与模拟账户

## 工作目标

帮助用户建立可追溯的短线观察流程：核验数据、计算信号、解释候选、检查当前时点、保存模拟计划并跟踪退出。先使用用户给出的预算、持仓数和持有周期；没有指定时采用默认研究配置，并在交付中写明。

MA5/20规则来自单只股票教学示例。全市场分配、流动性排序、持有上限和追价约束是本地扩展，尚未证明盈利有效。成交容量排名只能解释为流动性优先，不能解释为上涨概率或投资价值排名。

## 决策边界与用户意图

先分别提取本次请求的资金、候选展示数量、同时持仓上限、持有期限和研究跟踪数量，分别传入`--capital`、`--top`、`--max-positions`、`--max-holding-sessions`和`--research-size`。各参数独立：候选数量不决定仓位数量，持仓上限不要求买满。会话输入只用于本次运行或用户明确要求接续的同一账户，不得写回技能默认值、通用规则或跨会话偏好。未说明持仓数时明确披露模拟默认值，不能声称是用户的配仓选择。若预算假设会显著改变名单，在解释中说明其影响。

先分别回答“有哪些值得进一步研究的预选”和“是否已有足够买入依据”。未完成盈利验证不应清空研究预选，也不能每次只回答不推荐。正常筛选后读取`research_preselection`，有合格候选就交付具体名单、入选证据、反对证据及下一步核查重点；不足不凑满，数据不完整只称部分观察。用户说“推荐预选”时按研究预选处理，不把这句话当作必须输出实盘买入建议。

默认策略当前没有实现已验证买入建议的资格晋级验证器；`decision_review.recommendation_count`为0，`recommendations`为空，仅约束买入建议，不能作为省略研究预选的理由。开头按实际结果写“本次有N只研究预选；买入依据尚未验证”，不要一律用“暂无可推荐交易”替代交付。禁止仅因流动性第一就称首选、优先买入、最有机会、稳健推荐，或自行给出胜率、目标收益和止损价格。数据完整、公告正文采齐、报价约束通过、模拟计划建立、正收益和测试通过均不能自动授予买入资格。

无论买入建议是否具备资格，都要完成逐股研究解释：区分已知的入选原因与尚缺的交易论证：具体交易机会、支持与反对证据、入场触发、判断失效条件、退出时点、交易成本及损失范围。缺失字段标为未验证，不补造催化剂或主观评分来凑满名额。推荐可以为0，候选展示可以有6只；研究对照补位不增加推荐数量。强势走势也不能自动获得买入资格。读取已采集公告正文，与走势和持有期限综合解释研究价值；没有明确事件证据就写未发现，不把“盈利未验证”当作停止研究的理由。

持有参数控制退出流程，不会使选股逻辑自动适合该期限。当前`--max-holding-sessions N`表示买入日计第1天，第N天结束后安排下一交易日开盘尝试退出；不能写成“第N天内清仓”。用户明确要求第N天收盘前退出时，说明当前引擎不支持这一执行时点，不得宣称满足；需要独立策略实现与验证。天数上限和入场价格上限均不是最大亏损限制。

修改交易规则前读取[策略改进与验证规范](docs/strategy-validation.md)。先明确机会假设和验证方案，再实施独立版本；不得只因某只股票近期下跌，就事后添加排除条件并宣称更优。当前版本保持原筛选和模拟基线，增加走势诊断、逐股研究重点及买入资格边界。研究状态是描述性标签，不是新增选股门槛、收益排名或经过验证的新策略。规则有效性仍未验证。

## 执行入口

本技能供用户用自然语言调用。用户说“盘后筛选”“短线观察名单”“复核追价条件”或在宿主中显式调用`tail-screener`（例如Codex的`$tail-screener`、Claude Code的`/tail-screener`）时，读取用户的资金、席位和持有周期，执行下述入口并交付报告；不要只返回命令让用户自行运行。只要求查看已有报告时读取对应证据，不自动重新扫描。用户没有要求恢复历史时，不启动长期历史补抓。

先将本`SKILL.md`所在目录解析为真实绝对路径，作为技能根目录。即使从其他项目调用或技能安装目录是链接，也须从技能根目录运行；数据和账户沿用该目录的存储空间。Windows优先调用根目录`screen.cmd`，它负责寻找已准备的Python；其他宿主使用下述统一Python入口。辅助脚本属于技能执行资源，不要求用户手动敲命令。

### 首次环境准备

执行依赖仅为Python 3.10+及`requirements.txt`中的库，不依赖特定agent、模型、厂商SDK或模型API密钥。宿主需能读取技能资源、运行本地命令及访问免费行情源；遵守宿主的权限设置。

先探测已有的`python3`、`python`或Windows的`py -3`，实际检查版本，不根据名称推断。选择满足版本要求的解释器，后续使用其绝对路径。不存在合格解释器时，说明缺少Python及安装方式；不要静默使用宿主私有目录，也不要复制另一台机器的虚拟环境。

正常筛选直接运行`<解释器> scripts/screen.py`并传入用户参数，由入口检查、复用或准备依赖。`--doctor-offline`仅用于排查，它不安装；诊断发现缺少依赖不代表自动准备已经失败，也不能据此停止正常入口。HTTP库的发行名是`requests`，交易日历库是`exchange-calendars`；安装使用随包`requirements.txt`，不要根据口述名称安装`request`。缺少venv/pip、目录不可写或安装失败时，按[环境准备](docs/environment-setup.md)完成现场配置，保留实际错误，不循环重装，不禁用证书校验，不改系统全局Python包。

正常入口不执行发布清单比较，不先手工比对发布文件哈希。仅在排查发布来源时显式调用`--verify-package`；它对清单缺失、被改写及文件差异返回非阻断提示，不能据此停止、反复重装或自行重写清单。只有实际缺少必要程序/规则、程序不能加载、依赖或配置无效，以及本次行情和账户证据不合格时，才按相应错误处理。`--verify-release`仅供开发者发布验收，不能拿其结果阻断用户的正常调用。

### 运行请求

以本文件所在目录为工作目录，使用已核验的Python 3.10+解释器运行（示例中的`python`替换为实际解释器）：

```bash
python scripts/screen.py --top 6
```

Windows调用根目录的`screen.cmd`并传递相同参数，例如`.\screen.cmd --mode post-close --top 6`；启动器优先使用本项目已准备的环境。执行后读取`report.json`，向用户提供实际生成的报告链接，并说明数据日期、候选、账户及完整性；失败时保留诊断。用户侧调用示例见[使用说明](docs/usage.md)。

默认分发包是轻量技能包，直接附带必要规则，不含历史验收归档、行情缓存、账户或Python环境；日常启动不展开历史附件，也不先下载完整历史包。入口检查依赖并准备运行环境，采集近期完整日线及上市日期，保留原始响应、报价、核验结果及哈希。需要网络和可写空间。东方财富日线连接暂时失败时尝试腾讯原始与前复权日线；缺少明确复权字段时，需取得新浪对应证券的有效复权因子才能继续。源不可用或字段冲突时保留缺项。

用户参数通过命令行或另存的包外配置传入，并在报告中说明实际值。需要排查安装差异时，可运行`python scripts/restore_support.py --verify-package`；它只比较发布记录并提示差异，不安装、不联网、不阻断后续正常入口。实际运行使用安装后代码的实现哈希，保持账户版本隔离。

按用户条件运行，例如：

```bash
python scripts/screen.py --capital 50000 --max-positions 3 --max-holding-sessions 3 --top 6
python scripts/screen.py --config configs/account-config.json --capital 50000
```

| 参数 | 含义与默认值 |
|---|---|
| `--capital` | 初始模拟资金，默认100000元，最多两位小数 |
| `--max-positions` | 同时持仓上限，默认6，范围1至50 |
| `--max-holding-sessions` | 含买入日的持有交易日上限，默认5，范围1至60；到期后下一开盘尝试退出 |
| `--max-entry-gap-pct` | 入场价相对信号收盘的涨幅上限，默认3% |
| `--max-ma20-premium-pct` | 相对MA20的溢价上限，默认8%；用于筛选及冻结价格上限 |
| `--top` | 严格候选展示名额，默认6；不改变席位、资金或持有规则，边界精确并列全部保留 |
| `--research-size` | 独立研究跟踪名额，默认6，范围1至50；与严格候选数和持仓席位分别配置 |
| `--research-account-dir` | 独立研究账户目录；默认位于严格账户目录下的研究子目录，不能与严格账户相同 |
| `--mode` | `auto`、`live`或`post-close`；live额外标明当前是否处于连续交易时段 |
| `--daily-update-budget` | 日线采集秒数预算，默认600，范围30至1800 |
| `--run-budget` | 整次默认账户调用的总秒数预算，默认600，范围30至1800；包含环境准备，各阶段共享，预留报告交付时间 |
| `--daily-workers` | 日线滚动并发数，默认12，范围1至16；不改变筛选范围或规则 |
| `--data-source` | 默认`recent`近期日线；`archive`使用完整批量包并尝试补齐，首次包约568MB |
| `--output` | 新报告目录，必须为空 |
| `--data-cache` | 所选数据模式的缓存目录，默认自动管理 |
| `--source-cache` | 公共响应缓存目录，默认自动管理；与日线缓存同时指定独立空目录可验收首次采集 |
| `--account-dir` | 独立模拟账户目录；代码、配置或数据模式改变时不能接续旧账户 |

上述默认值是研究约束，不是已验证的最优参数，也不限定实际亏损幅度。用户只要求短线时，不要擅自承诺固定次日成交；设置1个持有交易日表示买入日结束后安排下一交易日开盘卖出尝试，停牌等情况会延后。

### 执行时限与进度

同一请求只启动一次正常入口，在宿主返回的同一进程或会话上等待后续输出；工具暂时让出执行不表示需要重跑。宿主的单次等待超时应继续查询原进程，不按证券批次拆成多次模型调用，不并发启动相同账户。除非用户明确要求延长，不自动增加`--run-budget`，也不在失败后循环重跑。入口的总时限覆盖环境准备、采集、核验和报告，不将`--daily-update-budget`当作整次调用的时限。

首次没有缓存时需逐股取得并核验原始与复权日线，网络延迟会显著影响耗时；不得用已有缓存运行的速度承诺首次云端运行速度。复用相同可写存储中仍有效的缓存，不保证不同宿主、任务或临时容器共享缓存。日线与公共响应缓存都为空才称为空缓存验收，并单独说明运行环境是否已准备。

只根据实际输出或`daily-inputs/progress.json`说明当前阶段、已核验输入数、未解决数和剩余预算。“日线输入已核验”不是通过全部选股门槛；筛选完成后才能引用`stats.bullish`和候选数。以阶段变化或有意义的间隔简述进度，不为每个批次重复规则长段解释。

到达总时限后读取实际生成的`report.json`、`index.html`、`run-control.json`和`execution.log`并交付。超时可能产生不完整的正常报告，或由运行控制器交付失败报告；两者都不能描述为完整全市场结果。失败报告中的空名单不表示零信号，账户状态需另核验。保留有效缓存、未完成输入和原账户，不改用昨天的数据、缩小范围或跳过公告来制造完整结果。

环境失败时保留具体阶段、退出码和错误，使用`--doctor-offline`检查已有环境；`--doctor`增加联网诊断。不要用诊断成功替代扫描验收。日常使用不要求`--restore-only`。只有用户另行提供历史资料归档并需要读取时，才执行该还原命令；轻量包中的`historical_materials=not_included`表示未附带历史资料，不是每日筛选失败。

## 本实验包的模型名单入口

本分发包提供用户要求的已有较好方案实验排序。完成上述正常入口后，读取[实验排序](docs/experimental-ranking.md)，在新的输出目录执行 `python scripts/rank_experimental.py --report 本次报告目录/report.json --output 新实验报告目录`，再交付实际模型名单及其原流动性名次。用户仅要求对已有报告重排时直接运行此只读入口，不重扫、不改账户。仅返回正常入口的流动性名单不能称为完成了实验模型选股。

模型为第06项33特征HGB的2021折，训练截止2020-12-15。已有三折研究平均净收益+0.0417%，去最高五笔后−0.1387%，没有通过原晋级门槛；以“实验研究候选”说明一次即可，不在每只股票下重复同一段说明。不要宣称最新市场训练或效果最优。本模型改变研究展示顺序，原模拟账户与交易资格继续按原规则处理。

读取用户实际持有期；当前模型只对应H2标签。其他期限保留用户输入，模型返回不适用，继续交付该期限的基线与K线分析，不能强制改成两天。资金、最大仓位和展示数也沿用本次输入；模型历史预算不作为全局默认。不同预算、入场设置或背景缺项由报告标识，不能套用原历史收益。原名单公告检查不自动覆盖新名单。持有两期仍沿用“满N期后下一开盘退出”，不要承诺第二天收盘前清仓。

## 检查数据与状态

读取生成的`report.json`，检查`requested_session`、`data_session`、`generated_at`、`run_status`、`data_issues`、`warnings`、`daily_refresh`、`stats`、`short_term`、`account_config`和`forward_account`。

- 盘中信号采用上一完整交易日；当前报价单独用于时点检查，不拼接进昨日均线。盘后必须核对实际日线是否到达目标日期。
- 连续交易时，在日线采集和资料补充结束后重新获取候选报价；原报价保存为`selection_quote`。刷新失败不得回退旧报价，并上报`candidate_quote_refresh`缺项。若运行跨过收盘导致目标日变化，`latest_complete_session_at_finish`会显示新目标，本次状态为不完整，应重新运行。
- 日线使用原始量价与完整复权窗口核验并重算；复权序列不构成现金分红或送股到账证据。近期模式只用于当前研究与后续记录，不具备全期历史回测覆盖。完整日线响应按目标日期最多缓存24小时；每次重新解析并与同日期新报价核对，冲突会强制刷新且失败不回退。读取`response_reused`和原`pair.fetched_at`，不要将复用称为刚从源头获取。
- `execution_status`表示程序完成情况，`data_status`表示本次数据检查情况。`complete`不表示公告正文、真实成交或盈利能力已经验证。
- `incomplete`时解释缺项及影响，名单只能作为部分观察结果。目录、筛选所需的日线与报价或当前账户净值存在缺项时，不冻结新模拟入场计划。
- `daily_refresh.status`核对当前筛选所需范围；`acquisition_status`单独保留采集缺项。已经由风险简称排除的证券，其缺失历史仍列于`scope_excluded_gaps`，不计作参与排名的完整数据。实际停牌区间可解释连续日线门槛不满足，但其他未核验日期仍保留，不据此估值持仓。不能将“筛选范围完整”写成“所有证券历史完整”。
- 腾讯日线与腾讯报价属于同一来源，匹配不等于独立来源复核；停牌接口提供的是数据商记录，不等于已取得交易所原始证据。报告应保留这些区别。
- `failed`表示本次扫描失败，不能解释为市场没有信号。失败报告和缓存保留用于诊断及恢复。
- 退出码：0为数据状态完整，1为不完整，2为扫描失败，4为环境准备失败；非零退出码仍可能生成报告。

默认账户的配置文件使用`schema_version: 1`，示例见[账户配置](configs/account-config.json)。命令行覆盖文件，文件覆盖默认值；未知、重复、错误类型和其他策略专属字段在联网前拒绝。未指定配置时不读取根目录旧策略配置。交付时解释`effective_configuration`中的实际值及来源。

## 解释候选与短线时点

入选需通过当前证券资格、至少252个交易日存续、20根完整合格日线、20日日均成交额至少1000万元、MA5>MA20、名义单席位最低股数及费用预算，以及配置的MA20溢价门槛。`stats.bullish`统计通过全部门槛的数量，不能写成“仅满足MA5>MA20”。

名义单席位预算按初始资金预留5%后除以`max_positions`计算；这仍是模拟模型的等额预算假设，不是用户指定的实际配仓比例。按本次资金和持仓上限计算并展示实际名义预算，不能用候选展示数量代替持仓上限作除数。保留最低股数、费用与实际现金约束，不能仅凭股价低说明适合用户。

按20日日均成交额、再按信号日成交额降序排序；精确并列保留，不足不补。展示`ma20_premium_pct`、`entry_price_ceiling`和`short_term_check`。价格上限在信号形成时冻结，后续不因高开而上调；超过上限不追价，也不递补较低排名股票。

同时展示`price_diagnostics`：近5交易日收益、收盘相对MA5/MA20、MA5较上一交易日变化、相对近20日最高收盘的回撤。使用同一复权收盘口径，不能直接混比原始股价与复权均线；数据不足时保留未核验，不把缺项填成0。下跌、跌破均线和MA5下行是需要解释的反对证据，不能以“成交额第一”抵消；这些指标只描述历史，不构成新增买入信号。MA5>MA20只代表均线状态，不要求新金叉、均线上行或股价站回均线。低于MA20不会被仅有上限的溢价门槛排除。

读取每只候选的`kline_review`，结合20根完整日线说明实体、上下影、前后包络、实体覆盖、突破后收回及量能。以数值和所处区间为依据，不凭图形外观自拟形态。先说明收盘是否突破或跌破此前5日高低区间，再说明成交额相对此前5日均额的倍数，最后结合均线、公告与用户持有期给出支持和反对证据。参考高低区间只作价格结构对照，不自动变成止损价或目标价。用户想看展示名单之外的股票时，读取`kline_catalog`或运行`python scripts/query_kline.py --report 报告路径 --group breakout --limit 20`检索全部严格合格候选；可改组别或代码。目录不受`--top`截断，按流动性排序，不增加模拟持仓；未逐股补齐公告的目录结果明确保留该状态，不混称完成买入论证。完整计算定义及离线入口见[日K线结构](docs/kline-analysis.md)。

正常报告自动展示同一批已核验OHLC生成的20根K线与成交额，不额外抓图、不把盘中报价拼入收盘K线。`kline_review.status=unknown`时保留缺项；旧报告没有此字段时不猜测、不补画。K线结构计算和收益排序分开：只有通过对应版本与资金期限验证的排序才可替换默认排序，形态名称本身不授予上涨概率。

`short_term.phase`区分开盘前、连续交易、午休、收盘后及非交易日。连续交易时检查报价日期及120秒时效；旧报价、未来报价、超过价格上限和全市场数据不完整均标明原因。检查通过仍只代表对应报价约束通过，不形成真实成交或买入推荐资格。

结合`observations`说明首次入选、已确认及连续确认天数、展示榜变化、规则失效和观察到期。跌出展示前N名不等于失效；数据未知、漏跑和同日修订不生成新的独立样本。默认观察期限5个交易日，独立于持仓退出。同日首次完整观察保持冻结，后续修订单独留痕；不要据观察变化改写原模拟订单。

`evidence_dimensions`分别表达执行、所需数据、正文采集、内容复核、条件化估值、策略有效性和真实成交。`mirror_bodies_collected`只表示镜像正文取得，不能解释为已完成语义复核。

检查每只候选的`body_review`、`distributions`、`review_gaps`及`errors`。程序采集近14日公告镜像正文，核对证券、编号、标题、分页和披露时间，保存原响应及哈希，并定位待复核词项。查看段落上下文和更正公告；词项命中不能直接解释为风险已经发生，未命中也不能解释为安全。正文采集不完整会传递到顶层状态并阻止新模拟计划。财务字段仍是数据商字段，正文取得不等于财务审计、合同真实性或订单收入已经确认。

## 研究模拟与严格账户

默认展示6只严格候选、最多持有6仓，同时保存独立的6股研究篮子。用户明确指定名额、持仓数、资金或持有周期时使用实际配置；跟踪名额不等于当天必须买满。两套账户各自使用配置的初始模拟资金，现金、持仓、费用和净值分别记录，不相加，不把研究对照成绩算成严格策略收益。

研究篮子先按成交容量选通过规则的股票，不足时从当前资格、252日存续、20根完整日线、流动性和名义可买性合格的证券中补入对照。对照逐只保存未通过的均线或MA20溢价条件，不能改称合格策略候选。容量精确并列时，研究篮子按代码稳定选满目标名额；严格排序仍保留精确并列。可计算证券不足时保留空位及原因，不拿过期行情或不合格证券补齐。

读取`research_simulation`和`research-simulation.json`。研究计划保留公告或严格审查缺项，即使严格账户阻断，也继续记录研究篮子及其独立计划。补入的对照不额外采集候选公告正文，标为`not_collected_for_control`；执行涉及的公司行动仍需按原引擎采集核验。研究入场上限仅为信号收盘加配置涨幅，MA20溢价作为标注；资金、最小股数、费用、时点、跳空、成交量、T+1及退出约束仍执行，不保证六只均成交。

只有开盘前实际冻结的研究计划能参与后续条件化成交，不回填过去买入。同一目标日沿用第一次计划；不每日强制换成新篮子，原持仓按退出规则处理。持仓缺价或事件未解决时逐股保留未知，已知持仓仍处理；净值或收益缺失不填零。`valuation_status`和研究账户指标单独解释，资料审查放行、真实成交和策略盈利均不能从研究计划推断。

资料包中的`account/`为严格账户、`research-account/`为研究账户，`continuation.research`单独标记研究接续状态。恢复时同时传入包内配置、两套账户目录和近期快照；完整命令见包内`USAGE.txt`。只保存名单不足以接续模拟账户。

## 解释账户与退出

- 在下一开盘前实际冻结的名单才可参与后续条件化模拟；错过时点不倒填买入，同一目标日保留首次计划。
- 共享现金、不借钱、不加仓、不每日重平衡，保留5%预算余量。新仓受席位、现金、净值、费用、价格上限和成交条件共同约束。
- 收盘MA5<MA20或达到持有天数上限后，下一开盘尝试退出；均线相等不触发均线退出，退出受阻则延后，遵守T+1。
- 日线、跳空与成交量只能支持条件化模拟，无法证明真实开盘价格、排队顺序或竞价分配。
- 自动读取已实施分红送转目录，并核对匹配的实施公告正文。支持已识别的现金与资本公积转增模板；核对股东实得权益、除权参考口径、到账与可售日期、自然人补税表或明确免税来源。送红股、零碎股分配、未知可售日、更正冲突及未支持的模板仍待核验。目录不覆盖所有公司行动，缺少记录不能证明没有事件，复权因子不能推造现金。
- 现金分红模型限定为2015年9月8日后、境内自然人从公开市场取得的普通流通股、整仓退出且不加仓。按登记日持仓记税前应收款，发放日入现金；未卖出时按当日假设卖出的持有期预留税款，卖出后固定模拟税额。预留税款不用于新买入。`dividend_tax_reserve_cents`和`real_withholding_verified`必须随净值一起解释；实际到账、扣税凭证及其他投资者税务未核验。
- 资本转增只在完整自然人税款表或股票发行溢价免税条款支持时入账，不将所有资本公积一律视为免税；新增股数不能有未解决的零碎分配。整仓卖出须等待明确的新股可售日。其他公司行动仍要求明确经济字段及最终净税款状态。缺失金额不表示零分红；数据商统一“扣税后”字段不表示本账户税款已结清。正文解析通过不等于公告已完整审计，新事件不能清除历史未解决事件。
- `metrics.valuation_complete`表示条件化模拟输入可以完整计算；同时读取`valuation_basis`和`corporate_actions_audited`。复权兼容不证明不存在公司行动，不据此声明真实净值已经完整审计。
- 结合`account-record.json`、`account-state.json`、`account-observations.json`核对现金、持仓、事件及估值缺项。本地哈希链可检查记录变动，不是外部时间公证。

单次运行不会自行持续监控或定时执行。不要连接券商或下实盘订单。

需要补齐已保存账户的事件后重算时，使用同一已准备好的Python环境运行：

```bash
python scripts/replay_account.py --account-dir 原账户目录 --output 新重放目录
```

重放先核验原哈希链和开盘前冻结的名单，再补采事件，结果写入`reconstruction/replay.json`。原账户不覆盖，不重新选股、不补造历史订单。缺少原逐日量价输入仍保留未知；重放是事后修复证据，不是当前策略的新前向成绩，也不能直接作为可接续的实盘账户。

## 交付

面向读者用中文交付，按以下顺序组织，提供实际HTML报告链接：

正常默认账户入口同时生成`run-bundle.zip`。必须把HTML与该资料包一同交付；单独下载HTML不会携带旁边的`report.json`和账户文件。读取`run-control.json`中的`delivery`确认打包成功，失败时明确报告交付缺项，不把扫描成功等同于资料已保存完整。资料包保留报告原字节、实际参数、截至本次报告的账户哈希链、近期模式快照及本次已保存公告证据。读取包内`bundle-manifest.json`的`continuation`和`USAGE.txt`，只有`ready`才说明具备同一实现版本的账户接续材料，不代表本次数据审查或策略收益已验证。新环境按包内相对目录指定配置、账户与日线缓存，保留旧记录，不改写哈希链。HTTP缓存、Python环境与连续观察数据库不随包迁移；其他旧外部证据不能因此宣称已完整归档。

1. 先说明本次研究预选数量和买入依据状态，再说明数据完整性、信号交易日及关键缺项。有候选就交付预选，不因盈利未验证而省略。研究预选、已验证买入建议和部分观察分别计数；不要用完整性通过来暗示可买入。失败和不完整必须显著说明。
2. 用简表展示候选名称与代码、信号收盘、近5日涨跌、走弱标记、模型价格上限、相对MA20的位置和主要待核对事项。称为观察名单，列名写“流动性顺序，非买入排名”；不要把模型上限写成建议买入价。零推荐、零候选与采集失败分别解释。
3. 按本次实际研究名额分别展示研究篮子、严格候选和两套账户，说明对照的未通过条件、空位及缺项。简述运行时点、用户资金及持有约束和下一步计划。只陈述记录中确认的状态，不把模拟计划写成真实成交。缺失净值显示未核验，不能填零。
4. 公告全文、参数来源、哈希、历史验证及重复的通用限制放在报告后部或折叠区，按需查看；影响本次完整性的关键问题不折叠隐藏。共用限制集中说明，避免每只候选重复长篇文字。

重排已有报告时保留原始数据和生成时间，明确标为版式预览，不暗示刚重新采集或更新账户。不要用“程序跑完”“软件测试通过”替代数据完整或收益有效结论。

历史报告和验证材料仅在用户提供时读取，先核对是否匹配当前`rule_sha256`；不匹配的资料只能作为旧版本记录。轻量包未附带旧业绩证据，不将其缺失解释为当前策略已经通过或失去某项收益验证。

需要查看恢复清单、补抓历史日线或运行默认账户离线开发实验时读取[研究工具操作](docs/research-tools.md)。历史恢复使用`recover_history.py`声明证券、日期和复权口径，保留分片与字段缺项。`acquisition_complete`允许有明确停牌解释，不能据此认定价格完整或净值可核验；停牌不生成价格。实验必须绑定登记、规则、快照和覆盖证据版本；此入口不生成独立前向或推荐资格。不将研究文档中未实现的假设当作可运行策略。

旧研究生成的历史名单使用`reconstruct_legacy_account.py`单独重建，保留原账户和名单，输出新的行情缺口与事件阻点。修复输入可能改变后续模拟成交；这类名单不是当时实际冻结的订单，旧规则重建也不验证当前全市场筛选。不得与`replay_account.py`的原事前计划重放混称。

仅在用户明确要求其他策略时指定`--strategy minervini-trend`、`connors-rsi2`或`legacy-tail`，不因数据不足、结果不好或名单不够而自动切换。
