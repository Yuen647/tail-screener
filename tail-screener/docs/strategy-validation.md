# 策略改进与验证规范

用于修改短线筛选、排序、资金分配或退出规则。此文档规定研究步骤，不是已完成的盈利验证，不授予推荐资格。

## 先固定交易假设

1. 明确目标持有时间、入场与离场时点；区分“持有N天后下一开盘退出”和“第N天收盘前退出”。
2. 每次实验只研究一个可证伪的机会假设，例如强势延续、回调后恢复或超跌反弹；分别登记，不能混用相互矛盾的入场理由。
3. 保留MA5/20状态加流动性排序为教学基线。若研究强势延续，将“近期动量、均线斜率或恢复站回均线能否改善扣费后目标持有期限内的结果”登记为待验证假设，不预设结论，不直接升级成买入规则。
4. 将交易可行性（资格、流动性、资金、股数、成交约束）与交易优势分开。通过可行性门槛不能当作收益评分。新的排序必须与其预测目标匹配，并用数据检验。

## 在看结果前登记

保存不可覆盖的实验登记：假设、策略与代码哈希、数据快照、历史股票范围、复权与公司行动口径、入场触发、取消条件、失效条件、退出规则、持有期计数、仓位算法、费用和滑点、比较基线、时间分割及通过/淘汰标准。

同时登记试过的参数与策略数量。通过标准必须有预先确定的数值、样本量及不确定性计算方式；未定标准不能用事后看起来好看的收益晋级。指标可包括扣费后期望收益、胜率与平均盈亏比、回撤、尾部亏损、交易次数、不可成交比例、换手和收益集中度。不能只报告胜率。

## 用未见数据检验

- 按时间分训练、验证、最终保留区间；持有窗口交叠时在边界留出隔离。调参只能使用训练和验证期，最终区间看过即不再是未见数据。
- 使用当时可知的证券范围、公告时间和价格；覆盖退市、停牌、风险警示及公司行动。不能拿今天存活的股票回推整个历史股票池。
- 信号形成后的成交才可计入，禁止收盘信号按同一收盘价无条件成交。计入最小交易单位、最低佣金、适用税费、滑点、T+1、涨跌停、停牌和卖不掉的情况；没有成交证据则标为条件化模拟。
- 对本次配置的资金与持仓上限单独核验最低股数和费用拖累。展示数量不进入仓位分配。报告名义等额预算假设，若改为风险预算须另行登记。
- 与原基线、同样交易约束下的简单对照及不交易比较。分上涨、下跌及横盘阶段检查结果，并分析对参数、成本与极端几笔交易的敏感性。
- 报告置信区间或其他预登记不确定性范围，处理同日股票与交叠交易的相关性；完整披露失败实验，不能只挑最好版本。
- 样本不足、数据覆盖不全或成本后优势不稳定时维持“未验证”，不要给出人工信心分替代缺失证据。

## 验证工具的边界

现有`validate_account.py`仅支持其声明的数据、登记和覆盖格式。先读`docs/research-tools.md`及脚本帮助；未实现的统计晋级与独立前向验证不能用文案或布尔值伪造。

近期20根日线足以计算当前描述性指标，不能用于证明全年、多市场状态或指定持有期限的策略有效性。长期历史采集必须作为明确的研究任务执行，声明范围和预算；用户仅要求当日筛选时不自行启动。

当前`decision_review.py`保留独立的研究预选及逐股核查重点，对已验证买入建议输出0条。研究预选数量不受买入资格字段控制；研究状态标签仅描述已有走势，不是经验证的收益排序。未来启用推荐之前必须实现并测试证据验证器，核验精确的策略、代码、期限、资金配置、数据与实验版本，以及独立前向结果；不能仅把`recommendation_eligible`手工改为true。

即使策略层通过验证，逐股仍须核查当前数据时点、公告语义、可执行入场条件、反对证据、判断失效条件、退出规则及损失情景。历史验证不保证个股盈利。候选不足或当下条件不成立时允许0条推荐。

## 保存与兼容

保留修改前源码、原报告、原模拟计划和账户哈希链。新实现形成新`rule_sha256`，不直接接续旧账户，不将旧版成绩归到新版。版式预览保留原数据日期，说明未重跑与未更新账户；不能把离线复核冒充最新扫描。

修改后运行参数分离、走势诊断、推荐阻断、缺失输入、输出一致性与旧数据重放测试。软件测试通过只证明实现行为，不能计入策略盈利证据。
