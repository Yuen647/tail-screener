# Skill 日常使用说明

项目的主要使用方式是在支持Agent Skills的agent中调用`tail-screener`技能，由代理运行采集、检查与报告流程；不需要用户自己操作终端。`screen.cmd`和Python脚本是技能的底层执行入口，手动运行是可选方式。

## 在对话里调用

显式指定技能并说明需求，例如：

```text
$tail-screener 帮我做今天的盘后短线筛选，展示6只候选。
```

按自己的预算运行，例如：

```text
$tail-screener 按5万元、最多3仓、持有上限3个交易日做盘后筛选，给我报告和数据缺项说明。
```

盘中可以说“用tail-screener复核最新报价和追价条件”；查看历史结果可以说“用tail-screener解释上次报告，不重新扫描”。使用自选参数时继续保持相同配置，才能延续对应模拟账户。

Claude Code使用相同的技能名，显式调用语法为`/tail-screener`，后面写相同需求。其他宿主使用其自己的技能选择方式；技能本身不指定模型。

## 安装与分享

默认分享轻量技能ZIP，内含必要程序、规则及说明。历史验收附件、测试集、运行环境、行情和模拟账户不随安装包上传；日常筛选不依赖这些历史附件。发布差异提示不阻断正常调用。


将发布包解压到准备长期保留的目录，不复制其他人的虚拟环境或账户。可以先让agent读取该目录的`SKILL.md`，并说“安装这个skill，按当前机器准备运行环境并检查是否可调用”。若机器没有Python 3.10+，先安装系统适配的Python；首次配置步骤见[环境准备](environment-setup.md)。

安装器只需标准Python，无需先安装业务依赖。在项目目录运行对应命令：

| 宿主 | 安装命令 | 默认技能父目录 | 显式调用 |
|---|---|---|---|
| Codex | `python install_skill.py --agent codex` | `~/.agents/skills` | `$tail-screener` |
| Claude Code | `python install_skill.py --agent claude-code` | `~/.claude/skills` | `/tail-screener` |
| 其他兼容宿主 | `python install_skill.py --skills-dir <宿主技能父目录>` | 由宿主决定 | 使用宿主语法 |

`~`为当前用户主目录。目录与语法依据[Codex技能文档](https://learn.chatgpt.com/docs/build-skills)及[Claude Code技能文档](https://code.claude.com/docs/en/skills)。安装后在新对话检查技能列表；没有刷新时重新打开宿主。安装器不更改宿主的模型、工具权限或全局设置。

发布包分为项目资源和发现入口。安装器按自身位置确定项目目录，在宿主技能目录写入小型入口及`runtime-location.json`，后者只在安装时记录当前机器的实际位置。运行时先读取绑定位置，再加载源`SKILL.md`；所有资源以源目录为基准，与对话当前目录无关。历史附件不会暴露为同名技能。项目目录应保留；仅复制生成的入口不能构成完整发布包。

项目移动后，在新位置运行相同安装命令并追加`--update`。已有非本工具管理的技能或手工修改过的安装文件不会被覆盖。推广时分享发布ZIP，不分享本机生成的`runtime-location.json`、`.runtime`、`.cache`或账户目录。其他agent仍需具备本地文件、命令执行及网络权限；只支持聊天或不能运行Python的环境无法完成采集。

也可不安装，直接让agent读取项目`SKILL.md`执行；安装用于后续在其他工作目录发现并调用。本技能不会自动设置每天运行。

## 首次运行与等待

首次日线与响应缓存为空时，需要逐股采集原始与复权日线；已有缓存的耗时不能代表首次云端运行。默认整次调用预算为600秒，覆盖环境准备、采集、候选资料和账户核验。日线采用12路滚动并发，并给报告阶段预留时间。网络仍可能使数据无法在预算内收齐，此时交付不完整或失败报告，不能视为全市场结果。

同一请求只运行一次入口，agent应继续等待同一进程，不应因一次工具等待结束就重启任务或拆成数千次模型调用。进度中的“日线输入已核验”不是入选数量。最终读取`report.json`及HTML；`run-control.json`记录总耗时和是否超时，`execution.log`保留实际执行输出。临时云容器的缓存可能在任务结束后丢失，技能不保证跨任务复用。

可在自然语言中指定“整次最多运行10分钟，超时也给报告，不自动重跑”。底层参数为`--run-budget 600`；只有用户接受更长等待时才提高。`--daily-update-budget`只是其中的日线阶段上限，不能延长总时限；`--daily-workers`只控制并发，不改变选股规则。验收真正首次采集时，应同时将`--source-cache`与`--data-cache`指向独立空目录，并使用独立模拟账户；虚拟环境是否已准备要另行说明。

## 如何阅读报告

先看研究预选及“买入依据检查”。当前默认策略照常交付通过筛选的预选名单，并逐股列出研究重点、入选证据和反对证据；不因盈利未验证而清空预选。已验证买入建议另行计数，当前为0。完整的数据状态或模拟入场计划不能替代买入依据。数据不完整时仅交付部分观察，不强行凑满。

资金、候选展示数、同时持仓上限和持有期限分别取自本次请求，互不推导；会话输入不写回技能默认配置。当前模拟的名义可买性预算按资金预留5%后除以持仓上限计算。配置N个持有交易日表示第N个交易日结束后安排下一交易日开盘尝试退出，不能保证第N天内卖出。

候选表的流动性顺序不是买入优先级。近5日涨跌、是否低于均线及MA5是否下行是历史走势证据；没有走弱标记也不代表已验证上涨优势。近期走势缺失时显示未核验，不填0。完善交易规则时按[策略改进与验证规范](strategy-validation.md)实施独立实验。

默认另有“6股研究模拟”区域，显示本次跟踪篮子、入组依据、空位、独立净值和下一步计划。严格候选不足时，研究篮子可补入均线或MA20溢价未通过的对照，逐只标明；原始行情、资格、流动性和名义可买性仍必须合格。严格名单保留全部原门槛，不把研究对照改称策略候选。

公告审查不完整仍保存研究计划和缺项，研究成交按冻结收盘涨幅上限检查；MA20溢价门槛在研究中只作标注。实际入场仍受价格、最小股数、现金、费用、跳空、成交量、时点和席位约束，跟踪6只不保证买满6只。持仓缺价或公司行动未解决时保留未知，其他持仓继续处理；未知净值及收益不填零。两套账户各自使用相同初始模拟资金，互不共享现金或合并净值。

`--top`默认6、`--max-positions`默认6、`--research-size`默认6，三个参数作用不同。首次研究篮子按通过规则优先，再按成交容量排序；精确并列时研究篮子用代码顺序稳定选满，严格排序仍保留并列。`research-simulation.json`记录研究篮子及独立账户，`research-account-*.json`保留状态和记录。

正常每日调用会同时更新两套账户；只运行一次不会自动在未来买卖。后续在同一可写存储、相同配置与实现版本下再次调用，才按新增交易日处理原计划。跨环境迁移时同时恢复`account/`与`research-account/`，并检查`continuation`和`continuation.research`各自状态。旧五股账户不改写为六股账户。

每次调用应同时取得HTML和`run-bundle.zip`。只保存单独HTML时，其中相对链接指向的JSON不会自动一同保存；需要保留或转移账户时，下载并保留整个资料包。

资料包包含`report.json`、可直接使用的`account-config.json`、参数来源、截至本次报告的完整账户哈希链、近期快照和本次已保存的公告证据，文件清单附SHA256。先看`bundle-manifest.json`中的`continuation.status`：`ready`表示具备同一Skill实现版本的接续材料，`not_available`或`blocked`不能承诺接续；`requires_external_archive`还需原历史数据包。它不改变报告中的数据完整性。

在新环境解压后，使用相同版本的Skill，在技能根目录运行：

```bash
python scripts/screen.py --config <资料目录>/account-config.json --account-dir <资料目录>/account --research-account-dir <资料目录>/research-account --data-cache <资料目录>/data/recent --output <新的空报告目录>
```

路径有空格时为整个路径加引号；自然语言调用时也可让agent按资料包中的`USAGE.txt`接续。实现版本不同会拒绝接续，保留原版本和原包，不重置账户冒充延续。资料包不包含全市场HTTP缓存、Python环境和连续观察数据库；观察摘要仍保留，连续观察记录在新环境重新建立。`run-control.json`中的`delivery.status`为`failed`时，应另行保留现有报告及账户文件，不能声称已经完成迁移备份。

报告按“结果概览 → 观察名单 → 模拟账户 → 数据核验”排列。

- 先看信号日期、完整性状态与当前阻点。失败或不完整时，不将空名单理解为市场没有信号。
- 名单用一张表对照信号收盘、模型价格上限、相对MA20的位置和公告待核对事项。容量顺序不是上涨概率排名；模型上限不是建议买入价。
- 需要了解某只股票时展开个股详情，再按需展开公告正文、财务字段和事件证据。正文已取得不代表内容已审核。
- 账户区显示模拟现金、净值、持仓及计划。参数来源、全部提示、历史验证和来源哈希保留在后面的折叠区。

已有报告可只重新排版，无需联网或更新账户：

```bash
python render_report.py <已有report.json路径> --output <新的空目录>
```

重排结果明确标为版式预览，保留原始生成时间和JSON原字节，不覆盖旧报告。正常每日调用会直接使用新版布局。

## 可选：手动执行底层入口

需要独立于对话运行时，Windows可双击项目根目录的`screen.cmd`，或在项目文件夹中打开PowerShell执行以下命令；不需要激活环境，也不要求`python`已加入PATH。命令行入口自动选择本项目运行环境，找不到时再查找宿主Python。

## 每天盘后运行

建议在交易日收盘后、免费源已更新当天数据时运行，例如19:00：

```powershell
.\screen.cmd --mode post-close --top 6
```

程序读取最新完整交易日，采集近期日线和公告，计算候选并保存报告。周末、节假日使用最近完整交易日；19:00也不能替代数据日期核对，若免费源未更新或有冲突，结果仍是不完整。通常需要数分钟，首次准备或免费源故障时可能更久，以实际日志为准。

结束时终端打印`html`和`report`的完整路径。打开该次`index.html`查看报告，也可在项目`reports`目录中按修改时间找到最新的`account_…`文件夹。每次建立新目录，旧报告保留。双击启动采用默认参数并在结束后等待按键，避免窗口立即关闭。

先看实际数据日期、完整/不完整状态和警告，再看候选、价格上限、退出条件及账户记录。名次按成交容量排序，不是预测上涨概率；所有入选证券还经过历史窗口、流动性、名义可买性和追价等过滤。

## 设置研究资金与持有周期

默认模拟资金10万元、最多5仓，含买入日最多持有5个交易日。需要其他配置时，例如：

```powershell
.\screen.cmd --capital 50000 --max-positions 3 --max-holding-sessions 3 --mode post-close --top 6
```

这里表示5万元、最多3仓、持有满3个交易日或均线转弱后，在下一开盘尝试退出；停牌等受阻情况会延后。`--top 6`只决定展示数量，精确并列可能多于6只，不会把3个持仓席位变成6个。

默认入场最多比信号日收盘价高3%，相对MA20最多溢价8%；可用`--max-entry-gap-pct`、`--max-ma20-premium-pct`调整。首次使用可采用默认值；这些值不是已验证的最优参数。

日常保持同一组参数即可延续对应的模拟账户。改变资金、席位、周期、追价参数或实现版本会进入独立账户系列。根目录`config.json`属于旧模式；默认账户不会自动读取它，优先使用上面的命令行参数。显式JSON配置示例为`configs/account-config.json`。

## 盘中复核与诊断

```powershell
# 盘中复核报价、时效和追价条件；信号仍基于上一完整交易日
.\screen.cmd --mode live --top 6

# 查看参数
.\screen.cmd --help

# 检查已有运行环境，不联网、不安装、不筛股
.\screen.cmd --doctor-offline
```

跨电脑使用时，需要Python 3.10+、网络和可写空间；本机复制出的虚拟环境不保证可在其他电脑直接运行，统一入口会尝试准备目标电脑的环境。其他系统可运行`python scripts/screen.py`，参数相同。

## 不完整结果如何处理

| 退出码 | 含义与处理 |
|---|---|
| 0 | 本次所需数据和账户检查完整；仍不代表策略盈利或真实可成交 |
| 1 | 数据、公告或估值不完整；报告可能已有部分候选，先读警告。源恢复后使用相同命令、新输出目录重跑 |
| 2 | 执行或参数错误；看终端错误和失败报告 |
| 4 | 环境或资料准备失败；先运行`--doctor-offline`查看诊断 |

不完整运行不能作为新的完整模拟入场计划。若手动指定`--output`，须使用一个新的空目录；不指定时程序自动生成。不要清理`.cache`中的账户和证据来消除警告；已有报告可保留作对照。

## 使用边界

工具用于短线观察、报价复核和条件化模拟账户，不连接券商、不自动下单、不自行定时运行。若使用模拟账户，需持续运行以实际留下开盘前的计划；过去未运行的日期不会补造成事前订单。

全期历史净值和策略盈利有效性未获验证，免费源也可能出现缺项或连接失败。应以每次报告的实际数据日期和完整性为准。工程验收记录与已知限制见[可靠性验收](reliability.md)。
